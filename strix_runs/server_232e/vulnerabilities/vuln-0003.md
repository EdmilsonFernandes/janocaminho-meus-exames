## Description

node-forge 1.4.0 is present via firebase-admin and fails to validate element count in nested DigestAlgorithm sequences during RSA PKCS#1 v1.5 signature verification (CVE-2026-85393, incomplete fix of CVE-2026-33894). Garbage bytes can be embedded to forge signatures for arbitrary messages under low-exponent RSA keys.

## Evidence

**Advisory evidence:** `CVE-2026-85393` applies to `node-forge` at installed version `1.4.0`. The advisory is fixed in `none published yet`.

**Transitive dependency:** introduced by the direct dependency `firebase-admin@12.7.0`.

**Dependency chain:** `firebase-admin@12.7.0 > node-forge@1.4.0`

**Usage analysis:** imported by application code; affected API usage unconfirmed. Dependency edge verified: node_modules/firebase-admin/package.json lists node-forge in dependencies; firebase-admin is a direct dependency in package.json (^12.7.0) used for push notifications. Application code search (rg over src/) found zero imports of node-forge and no certificate/RSA signature-verification flow reachable from request handlers. The vulnerable symbol is not called by application code; the only consumer is firebase-admin internals whose inputs here are FCM device tokens and the Firebase service account (operator-controlled, stored at repo root). This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

If any reachable code path passed attacker-controlled signed material into node-forge's RSA verification, signatures could be forged. No such path was identified in this codebase; the finding documents the vulnerable dependency for upgrade tracking.

## Contextual CVSS

node-forge 1.4.0 is a direct dependency of firebase-admin (node_modules/firebase-admin/package.json dependencies list node-forge), which the app imports for FCM push notifications. I searched src/ for imports of node-forge: none — the app itself never calls node-forge APIs directly, and I found no code path where firebase-admin feeds attacker-supplied certificates or RSA material into node-forge's PKCS#1 v1.5 verification (push-token registration sends only device tokens, not certificates). The vulnerable symbol is therefore present in node_modules but has no demonstrated attacker-controlled call path in this codebase. Per the reachability rubric this is reported as imported with the trace documented and the impact scored conservatively: integrity:L only, high complexity, because exploitation requires a low-exponent RSA key in a path this app does not appear to exercise.

## Remediation

Track the upstream node-forge fix (incomplete fix of CVE-2026-33894; no fixed release at scan time) and upgrade once published, or override the transitive resolution to a patched build if one ships. No application-side change is required while no signature-verification path reaches node-forge.

## Assumptions

Advisory data verified against the trivy-offline GHSA/Red Hat database (web search unavailable in this sandbox); installed version 1.4.0 confirmed from node_modules; no fixed version published yet at scan time. Exploitability would additionally require a low-exponent RSA key in a signature-verification flow reachable by attacker-supplied data.
