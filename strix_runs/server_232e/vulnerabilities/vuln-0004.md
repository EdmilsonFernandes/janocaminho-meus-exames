## Description

deepmerge-ts 7.1.5 (transitive via @prisma/config and html-to-text) lacks visited-object tracking in deepmerge/deepmergeCustom/deepmergeInto, allowing stack exhaustion on self-referential object graphs.

## Evidence

**Advisory evidence:** `CVE-2026-40345` applies to `deepmerge-ts` at installed version `7.1.5`. The advisory is fixed in `8.0.0`.

**Transitive dependency:** introduced by the direct dependency `@prisma/client@6.19.3`.

**Dependency chain:** `@prisma/client@6.19.3 > @prisma/config > deepmerge-ts@7.1.5`

**Usage analysis:** not imported by application code. rg over src/ found no import of deepmerge-ts. Dependents verified from node_modules: @prisma/config/package.json and html-to-text/package.json declare it. html-to-text is itself not imported by application code. @prisma/config's usage is internal to the Prisma toolchain operating on repo-local configuration, not request data. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

No attacker-reachable path identified in this codebase; documented for dependency hygiene and upgrade tracking.

## Contextual CVSS

deepmerge-ts 7.1.5 is present only as a transitive dependency of @prisma/config and html-to-text (verified from node_modules/*/package.json dependency edges); the application's package.json does not list it and rg over src/ found no import of deepmerge-ts. @prisma/config's use of the package is internal to the Prisma CLI/config loading (operator-controlled config files, not request input), and html-to-text is not imported by application code (the mailer has its own hand-rolled htmlToText at src/utils/mailer.ts:33). No attacker-controlled entry point reaches the vulnerable merge APIs, so availability is scored L as a worst-case stack exhaustion with high attack complexity, and confidentiality/integrity are N.

## Remediation

No urgent action; upgrade @prisma/client (which will pull a fixed deepmerge-ts tree) during the next routine dependency refresh.
