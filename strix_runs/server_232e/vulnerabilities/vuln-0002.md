**CWE:** CWE-400

## Description

nodemailer is pinned to 9.1.1, which is inside the affected range of a quadratic-complexity address-parsing DoS (CVE-2026-90776 / GHSA-v53p-9fqp-m79j). This application feeds attacker-influenced email addresses into nodemailer on several flows.

## Evidence

**Advisory evidence:** `CVE-2026-90776` applies to `nodemailer` at installed version `9.1.1`. The advisory is fixed in `10.0.6`.

**Dependency chain:** `nodemailer@9.1.1`

**Usage analysis:** a call path from application code to the vulnerable function was proven. Source-to-sink trace: POST /api/public/lead (src/routes/lead.routes.ts:47, client-supplied `email` validated only by a basic regex) and POST /api/auth/register (attacker's own email) → sendWelcome/sendEmail (src/utils/mailer.ts) → nodemailer transport.sendMail({ to: email }) → addressparser quadratic path. Authenticated vector: src/jobs/reminderEmails.ts:71 sends to owner.email; password-reset and verification flows likewise use the registered address, which the user controls. The addressparser sink is exercised on every sendMail call, so the vulnerable code path is imported and executed routinely. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

An unauthenticated attacker (lead form, signup) or low-privilege user (reminder/verification mails to their own registered address) can submit a crafted address string that blocks the Node.js event loop for several seconds per request; repeated submissions starve the single-process API and degrade all endpoints for all tenants of this health-data service.

## Contextual CVSS

nodemailer 9.1.1 is imported at src/utils/mailer.ts:1 and sendEmail() passes the attacker-controlled `to` string into nodemailer's address parsing on every outbound mail. The attacker-controlled entry points are unauthenticated or free-signup flows: POST /api/auth/register (attacker chooses their own email), the password-reset flow (attacker requests reset to their own address), POST /api/public/lead (source-gated but email is client-supplied), and email-driven exam upload. A crafted local-part/domain containing RFC 5322 comment-separated atoms or a long whitespace-free run without '@' hits the quadratic path in addressparser, blocking the single Node.js event loop for seconds per request. Because the entire API shares one event loop, event-loop starvation degrades every endpoint, not just email (A:H). No confidentiality or integrity impact is demonstrated. privileges_required:N because registration and lead capture are open.

## Remediation

Upgrade nodemailer to >= 10.0.6 (fixes both CVE-2026-90776 and GHSA-v53p-9fqp-m79j). As defense in depth, validate/normalize recipient addresses with a strict RFC 5322 subset before passing them to nodemailer, and cap local-part length.

## Assumptions

Advisory data verified against the trivy-offline GHSA database (web search unavailable in this sandbox); installed version 9.1.1 confirmed from node_modules. Exploitability assumes the attacker can control a recipient address that the app feeds to nodemailer — satisfied by signup email, password-reset recipient, and account deletion.
