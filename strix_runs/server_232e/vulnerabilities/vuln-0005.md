# uuid 10.0.0 out-of-bounds write with caller-provided buffers (CVE-2026-41907) — transitive, not imported

**ID:** vuln-0005
**Severity:** INFO
**Found:** 2026-10-08 13:14:02 UTC
**Target:** /workspace/server
**Package:** uuid
**Ecosystem:** npm
**Installed Version:** 10.0.0
**Fixed Version:** 11.1.1
**Introduced By:** firebase-admin@12.7.0
**Dependency Chain:** firebase-admin@12.7.0 > uuid@10.0.0
**CVE:** CVE-2026-41907
**CWE:** CWE-787
**Advisory CVSS:** 7.5
**Contextual CVSS Vector:** CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:N/I:N/A:N
**Fix Effort:** Low

## Description

uuid 10.0.0 (transitive via firebase-admin/gaxios) does not reject out-of-range writes when v3/v5/v6 accept caller-provided output buffers (CVE-2026-41907).

## Evidence

**Advisory evidence:** `CVE-2026-41907` applies to `uuid` at installed version `10.0.0`. The advisory is fixed in `11.1.1`.

**Transitive dependency:** introduced by the direct dependency `firebase-admin@12.7.0`.

**Dependency chain:** `firebase-admin@12.7.0 > uuid@10.0.0`

**Usage analysis:** not imported by application code. rg over src/ found no import of uuid (application uses crypto.randomUUID, e.g. src/routes/analysis.routes.ts share-token generation). Dependents verified from node_modules package.json edges: firebase-admin, gaxios, gcp-metadata, google-gax. None of these receive caller-provided output buffers from request handlers in this app. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

No attacker-reachable path in this codebase; documented for dependency hygiene and upgrade tracking.

## Contextual CVSS

uuid 10.0.0 is present only as a transitive dependency (dependents verified from node_modules: firebase-admin, gaxios, gcp-metadata, google-gax, nanoid re-exports). rg over src/ found no import of uuid; the application uses crypto.randomUUID() and its own generators instead. The vulnerability requires the application to call uuid v3/v5/v6 with an externally supplied output buffer and attacker-influenced offset — neither the app nor, to my inspection, any dependent's reachable path does this with request data. All impact metrics are therefore N with high attack complexity, reflecting a supply-chain hygiene item rather than a reachable flaw.

## Remediation

No action beyond routine upgrades; the next firebase-admin refresh will carry a fixed uuid.

## Assumptions

Advisory data verified against the trivy-offline GHSA database (web search unavailable in this sandbox); installed version 10.0.0 confirmed from node_modules. The application never imports uuid, so the precondition (calling v3/v5/v6 with caller-provided buffers) is not met anywhere in this codebase.
